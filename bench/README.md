# ベンチマーク（jabberwock build・Go・C++）

同じ処理を `jabberwock/`・`go/`・`cpp/` に書いたもの。`./bench/run.sh [名前...]` で、全部を作って走らせ、Markdown の表を出す（`$BENCH_OUT/results.md` にも書く）。
`RUNS=回数`（既定 5）・`JW=jabberwock の場所`・`BENCH_OUT=作業フォルダ`。出力が C++ と違えば `!!` の行が出る。
要るもの: `cargo build --release` 済みの jabberwock・clang（clang++）・cc・go。時間と最大メモリは `measure.c`（fork して `wait4` の rusage を読む。Linux 用）で取る。

| 名前 | 中身 | 主に見るもの |
|---|---|---|
| fib | fib(40) | 関数呼び出し（呼び出しの深さの確認） |
| bst | 二分探索木に 100 万件入れて 200 万回探す | own の区画の確保・`Option<own T>`・ref の世代チェック（データが大きく、キャッシュミスが多い） |
| binarytrees | 深さ 18 の二分木を作っては捨てる（benchmarks game の binary-trees と同じ手順。1 スレッド） | 小さい区画の大量の確保と解放・使い回し |
| sort | 300 万個の i64 を `sort()` | リストと並べ替え |
| sieve | 2000 万までのエラトステネスのふるい | `bool[]` の添字 |
| matmul | 600×600 の行列の積（f64 のリスト） | 添字の範囲の確認とリストの頭の読み直し |
| spectralnorm | n = 2000 の spectral-norm（10 回） | 小数の計算と添字・`ref f64[]` の引数 |
| nbody | 5 つの天体の n-body を 500 万歩（benchmarks game の n-body と同じ手順・同じ計算の順。最初と最後のエネルギーを 10⁹ 倍した整数で出す） | 構造体のリストの要素のフィールドの読み書き・`sqrt` |
| particles | 1 万個の構造体のリストを 1 万回動かす（`ps[i].x += ...`） | 構造体の要素のフィールドの書き換え・リストの要素を借りる印 |
| words | `"w{n}"` を 500 万回作って辞書で数える | 文字列の組み立て・辞書 |
| chan | 500 万個の i64 をチャンネルで送る | スレッドとチャンネル |
| concat | `s += "v{n},"` を 300 万回して 1 つの文字列を作る（Go は `strings.Builder`） | 文字列を後ろに足す（その場で足す `append`） |

- Go と C++ は、それぞれの普通の書き方（Go の `map`・`slices.Sort`・バッファつきチャンネル、C++ の `unique_ptr`・`std::sort`・`unordered_map`）。
  C++ のチャンネルは jabberwock と同じ「上限なし」を錠と条件変数で書いたもの（Go だけバッファつきで、条件はそろっていない）。
  C++ の `vector<bool>` はビットで詰めるので、sieve は C++ に有利（メモリも 1/8）。
- jabberwock は 3 通りで作る（`jabberwock build` の測定用の切り替え。`jabberwock build --help`）:
  - **jabberwock**: ふつう（解析で消せる世代の検査を消す）。
  - **検査を全部残す**: `--no-elide`（解析をしない）。解析が取り戻した分が分かる。
  - **検査を全部消す**: `--unchecked`（世代の検査も添字の範囲の検査もしない。**安全でない**。検査の費用の上限を見るだけ）。
- 検査の数: 「場所」は書き出した検査の数（`--stats`）、「実行時」は実際に通った回数（`--count-checks` で作った別の実行ファイル。数えるぶん遅いので時間は見ない）。
  世代の検査は ref をたどるときと、読むだけの写し（for の要素など）の own をたどるときにある。本物の own をたどるときは検査がいらない。

### 読み方

- **ぶれ**: 同じ実行ファイルでも最小と最大で 10〜20% 動く（クラウドのコンテナで、周波数もほかの負荷も止められない）。10% 以内の差は誤差と見る。
  10-23 の数字より全体に遅い（C++ の fib も 0.19 → 0.31 秒）のは環境の違いで、比べるのは同じ回の中だけにする。
- **世代の検査の費用**: 解析が効くのは particles（全部残すと 0.12 → 0.18 秒）と nbody。spectralnorm も 8 か所すべてを消せているが、
  もともと費用が小さい。bst と binarytrees は検査が実行時に 3〜4 億回通るが、消しても速くならない（キャッシュミスや確保の費用に隠れる）。
- **n-body**: jabberwock 0.35 秒は C++ と同じくらいで、Go（0.44 秒）より速い。解析が効いていて、検査を全部残すと 0.44 秒になる
  （世代の検査が実行時に 12 億回通るところを、解析で消している。残った 150 回は最初と最後のエネルギーの計算の `ref bs[i]`）。
- **添字の範囲の検査の費用**: matmul で 0.089 → 0.077 秒（約 13%）。ほかは誤差の範囲。
- **最大メモリ**: binarytrees は Go・C++ より小さい（解放した区画をすぐ使い回す）。sieve は C++ の `vector<bool>` がビットで詰めるので C++ が小さい。
  chan は jabberwock と C++ が上限なしのチャンネルで、送る側が先に進むぶん大きい（Go はバッファつき）。
