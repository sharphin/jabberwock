# ファイル入出力ライブラリの設計

状態: 実装前の設計。以下の型・API・設定は提案であり、利用可能な機能ではない。
[全体方針](standard-libraries.md) と [共通資源管理](resource-management.md) に従う。
Windowsを先行し、Linuxでも共通の処理と安全性を検証する。外部Rustクレートは追加しない。

## 範囲と互換性

既存の `read_file(path)` はUTF-8の一括読み込み、`write_file(path, text)` は上書きである。
既存の公開名・戻り値を保ち、新しいファイルAPIとは区別する。既存組み込みを新しい内部処理へ切り替えるときは、
空ファイル、エラー表示、文字コード、パスの扱いについて互換性試験を行う。

初期範囲は通常ファイルのバイナリ・UTF-8一括入出力、開いたファイルの逐次入出力、位置・長さ、
明示的なflush・sync・close、ディレクトリ列挙・作成、明示的な削除・名前変更。
メモリマップ、監視、ファイルロック、非同期I/O、圧縮、デバイス・名前付きpipeは後の範囲とする。

## 値とAPIの草案

| API・型 | 契約 |
|---|---|
| Path | OSのパス表現を保持する不透明な値。ファイルの所有者ではない |
| `Path.from_text(text)` | NULを拒否してOS表現へ変換。文字列の長さとOS側の長さも確認 |
| `Path.to_text()` | 正しく変換できる場合だけUTF-8を返す。変換失敗を置換文字で隠さない |
| `Path.display()` | 診断用の表示。これを開き直し用の文字列として保証しない |
| `read_bytes(path, limit)` | 上限内の `u8[]` を所有して返す |
| `read_text(path, limit)` | バイト数の上限と厳密なUTF-8検証を行う。BOM・改行は勝手に取り除かない |
| `write_bytes(path, data, mode)` | 明示した作成・上書き規則で全量を書き、明示的な完了・失敗を返す |
| `open(path, options)` | `Result<File, IoError>`。成功時だけFileの所有値を返す |
| `File.read(max_bytes)` | `Result<ReadChunk, IoError>`。DataとEofを区別する |
| `File.write(data)` | 1回の書き込みで確認できたバイト数。短い書き込みを許す |
| `File.write_all(data)` | 全量を試みる。失敗時は確認済みの進捗も返す |
| `File.seek(offset, origin)` | 位置を返す。負の最終位置と計算のあふれを拒否する |
| `File.length()` / `set_length(n)` | 長さの取得・変更。変更は書き込み権限を必要とする |
| `File.flush()` / `sync()` | 下記の異なる保証を持つ |
| `File.close()` | 所有値を消費する。close後の所有値・別名では利用できない |
| `read_dir(path, limit)` | 所有するEntryの列。返したPathは列挙終了後も使える |
| `create_dir` / `remove_file` / `remove_empty_dir` / `rename` | 操作を明示する。再帰削除は初期APIに含めない |

ReadChunkのDataは空でない。max_bytesが0以下なら呼び出し前にInvalidArgumentを返す。
空のデータを書き込む操作は0バイト成功とする。非空のwrite_allで進捗0が続く場合は無限ループにしない。
バイト列の途中でUTF-8の文字が切れるため、File.readの各チャンクを独立した文字列へ変換しない。
状態を持つテキストストリーム・行iteratorは、別途復号状態と行長上限を設計してから追加する。

## パスとディレクトリ

WindowsではUTF-16、LinuxではOSのバイト列を、Pathの内部に損失なく保持する。
Windowsの不正なサロゲートやLinuxの非UTF-8の名前を列挙できても、to_textが成功するとは約束しない。
EntryのPathをそのまま再利用し、表示文字列から復元しない。

- Unicode正規化、大文字小文字の変換、記号の置換をしてファイルの同一性を変えない。
- 相対パスは操作時の作業ディレクトリに依存する。Pathの作成だけで絶対パスへ固定しない。
- パスの連結・絶対化・実体の解決を区別する。文字列の正規化だけで安全な領域へ閉じ込められたと扱わない。
- UNC、長いパス、reparse point/symlink、予約名の扱いはWindowsの結合試験で明記する。
- 初期実装は通常ファイル・ディレクトリを対象とし、開いた対象の種別も確認する。
- read_dirは列挙途中の失敗を返す。列挙順はOS依存であり、必要なら利用者が並べ替える。
- 列挙中の追加・削除を含む完全なsnapshotは保証しない。Entryの種別は取得時点の情報とする。

read_dirのEntryが持つ名前・Path・種別は所有する値とし、OSの列挙バッファへのrefを外へ出さない。
削除はlinkの対象を暗黙に再帰削除しない。renameは上書き可否を明示し、別ファイルシステムへの移動を
コピーと削除へ黙って切り替えない。

## 開くモード

OpenOptionsは読み取り／書き込み、作成規則、append、OS固有の共有規則を区別する。
作成規則は既存のみ・存在しなければ作成・新規のみ・既存を切り詰め・作成または切り詰めを候補とする。
切り詰めとappendには書き込み権限を必要とし、矛盾した指定をOS呼び出し前に拒否する。

新規のみはOSの排他的作成で実装し、exists確認と作成を分けない。
appendはOSのappend機構を使う。seekして末尾へ移動してからwriteする方式で代用しない。
appendのFileに対するseekは初期APIでは拒否する。複数write_all間の非混在や、ネットワーク共有上での
同じ原子性までは保証しない。
Windowsの共有規則は既定で読み・書き・削除の共有を許す案とし、POSIXのファイルロック相当とは扱わない。
既存の一括書き込みは上書きの互換性を維持する。新APIのmodeは省略で破壊的なモードに決まらないようにする。

## 所有・別名・スレッド

Fileは不透明なムーブする資源型。整数のfd/HANDLEやFILEポインタは公開しない。
読み書き・seekなど位置を変える操作は可変借用を要求する。ただしref mutは排他的でないので、runtimeでも
Open/Busy/Closedを検査し、再入・close中の操作・異なる種類の資源を拒否する。
初期段階ではFileを送信不可とし、worker内で開いて、取得したバイト列や文字列だけをchannelで返す。

一度しか解放しないこと、失敗途中に確保した資源も解放すること、世代の再利用で古い借用を復活させないことは
[共通資源管理](resource-management.md) の契約とする。OSの番号が同じになっても同じ資源とは扱わない。
Path・Entry・ReadChunkはOSハンドルを含まない所有値とし、必要な送信・複製の意味を別に定める。

## 短い入出力と失敗

一度のread/writeで要求した全量が処理されるとは仮定しない。OSが報告した長さを範囲検査してから使う。
再開可能な割り込みだけを、OSの契約に従って再試行する。処理済みか分からない書き込みを先頭から繰り返さない。
write_allの失敗は、確認済みバイト数と、それより多く書けた可能性があるかを区別する。

IoErrorはNotFound、AlreadyExists、PermissionDenied、InvalidPath、InvalidEncoding、WrongKind、Closed、
Busy、Unsupported、LimitExceeded、NoProgress、OsErrorなどの種類と、安全な操作名を持つ。
WrongKindは通常ファイル・ディレクトリなどOS対象の種類の違いを指す。内部tokenの偽装とは区別する。
OSごとに文面が変わるエラー文字列だけでプログラムを分岐させない。ネイティブエラー番号は存在する場合の補足情報とする。
失敗したreadで未初期化部分を公開しない。失敗した一括readで部分的な内容を成功として返さない。
途中まで書けたファイルを、自動で元に戻せたとは扱わない。

## 上限と永続化

一括readとread_dirは上限を必須とし、初期の一括read上限の候補は64 MiBとする。
ファイルの初期サイズだけを信頼せず、読み込み中の伸長も上限で止める。
長さ・位置・OS側引数の幅の変換と確保の前に、範囲・加算・乗算を確認する。
上限を超えた結果を切り詰めて成功として返さない。

flushはライブラリ側の未送信のバッファをOSへ渡す。syncはOSへ永続化を要求する。
初期のFileを非バッファ方式にする場合も、この区別を保つ。
close成功だけで電源断に対する永続性まで約束しない。ファイル内容・名前変更・ディレクトリの永続化は別の条件である。
一時ファイルと置換によるatomic writeは、同一ボリューム・共有規則・syncの順を設計してから追加する。

dropは後始末であり、書き込み成功を通知する手段にしない。明示flush/sync/closeで失敗を受け取る。
既存のexitと実行時エラーでは通常の後始末をしない。ドキュメントの追加だけでこの挙動は変更しない。
通常の同期I/OでもOSやネットワーク共有で待つことがあり、厳密な操作期限は初期範囲には含めない。
GUIではブロックしうるI/Oをworkerへ分ける。

## 実装と検証

共通のC側のファイル処理をRust/IR/ネイティブ/jwcから利用する案とする。
Windowsはワイド文字のOS API、Linuxは対応するファイルAPIを使い、OS固有の意味の違いを無理に同一と説明しない。
aliceはファイル能力・runtime/ABI・対象環境を [ビルド指紋](alice-native.md) に含める。

| 試験 | 完了条件 |
|---|---|
| バイナリと文字 | 0バイト、全byte値、日本語、不正UTF-8、境界で切れる文字、BOM・改行を保持 |
| モード | 存在しない／既存のファイル、排他的作成競合、切り詰め、append、矛盾した設定 |
| 部分処理 | 短いread/write、途中の失敗、進捗0、失敗後の内容と確認済み長さ |
| パス | 空・NUL・非ASCII・変換できない名前、長いパス、相対パス、UNC、link、対象種別 |
| 位置と上限 | EOF、負のseek、あふれ、上限直前・同値・超過、読み込み中の伸長 |
| 資源 | move/drop/close、二重close、別名、再入、番号の再利用、スレッド誤用 |
| ディレクトリ | 空、途中の変更・失敗、列挙上限、所有するEntry、空でないディレクトリの削除拒否 |
| 保存 | flush/sync/closeそれぞれの失敗を注入し、保証を混同しない |
| 実行器 | 独立した作業ディレクトリでRust/IR/ネイティブ/jwcの結果・診断・解放を比較 |

既存のデバッグ比較で実際のファイル操作を何度も行う問題を、[共通資源管理](resource-management.md) の
外部副作用の規則に従って解決する。試験は使い捨てディレクトリで行う。
安全性1〜7のCIへ資源の誤用、失敗注入、生成入力を追加する。OSごとの未実施構成は成功に数えない。

この文書は設計であり、新しいFile APIを実装・検証済みという報告ではない。
