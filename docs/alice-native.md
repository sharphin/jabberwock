# aliceのネイティブ依存・ビルド管理の設計

状態: 実装前の設計。設定名・配置・コマンドの拡張は案であり、現行aliceの機能ではない。
[パッケージの現仕様](packages.md)、[全体方針](standard-libraries.md)、[共通資源管理](resource-management.md) を前提とする。

## 現状との差

現在はローカルのパス依存、平坦なモジュール、直接依存だけを使える名前空間を持つ。
ビルドの再実行はソース・manifestと出力の更新時刻を比較する。
コンパイラ・埋め込まれたruntime・オプション・外部ライブラリの変更をすべて判定できる仕組みはまだない。
この設計では既存のパス依存を維持し、ネイティブ能力と内容に基づくビルド指紋を追加する。
標準と同梱パッケージの配置、bundledによる依存指定、可視性、解決済みグラフは
[標準ライブラリの配置・読み込み仕様](standard-library-loading.md) に従う。
ネット取得、パッケージレジストリ、任意のビルドスクリプト、初期のcross compileは対象外とする。

## 能力の宣言と選択

能力IDの候補はfs、net、tls_client、postgres、window、draw2d、image、guiとする。
能力ごとに、対応する対象環境・ABI・内部ソース・リンク指定・配布物を、ツールが知る定義に登録する。
たとえばguiはwindowとdraw2dを必要とし、Windowsのdraw2dはD3D11/DXGI/Direct2D/DirectWriteを利用する。
postgresのTLSはlibpqの依存であり、netのTLSクライアントと無条件に同じ能力とは扱わない。
imageはencoded画像の復号用の追加能力。raw pixelだけの描画には要求せず、WindowsではWICなどの依存を登録する。

パッケージは要求する能力を宣言する。machine固有のSDK/DLLの場所は、アプリ側・利用者側の設定で解決する。
依存パッケージに任意のDLLやCコードを選ばせる仕組みにはしない。
設定の表現例は次の案とし、実装時に正式なmanifest仕様を定める。

```toml
# パッケージが要求する能力。現在のaliceでは未対応。
[native]
capabilities = ["postgres"]
```

- 最初の入口と実際に読み込んだモジュールから、所属パッケージの能力を集め、その推移的依存を求める。
- manifestに名前があるだけの未使用パッケージを、無条件にDLLロードの理由にしない。
- 読み込んだパッケージ内では、未使用関数を安全に除去できたと仮定せず、要求する能力を含める。
- 直接依存だけがuseできる規則は保つ。native能力を宣言しても、言語モジュールの可視性を迂回できない。
- 未知の能力、未対応の対象、必要な依存の不足は明確なエラーにし、無視して通常のビルドへ戻らない。
- ネイティブ能力はOSの権限制御やサンドボックスの代用ではない。

現行のmanifestパーサーは未知の節・キーを読み飛ばす。
そのため、新manifestのversion番号だけで旧aliceが必ず拒否すると約束しない。
新ライブラリにはコンパイラが検査する資源ABI要求も必要とし、古いコンパイラでは解決できない形で失敗させる。
実際の記法と最小対応版を、新manifest・ライブラリ・各コンパイラで同時に導入する。

## 設定の優先順位

初期案は、明示したコマンド設定、プロジェクトのmachine設定、利用者設定、登録済みのOS既定値の順にする。
これらの優先順位を診断に示し、依存パッケージの設定を最終アプリの設定より優先しない。
最初はhostと同じtargetだけを許し、Rust側のhost名だけでC compiler/DLLのtargetを決めない。

設定で扱うのは対象環境・SDK・ヘッダー・ネイティブライブラリ・配布方法など。
DBのDSN・パスワードや、アプリの接続先はビルド設定と指紋へ含めない。
任意のcompiler/linker引数をmanifestから実行する機能は初期範囲には含めない。
既存のJW_CLANG/JW_CFLAGSの扱いも明文化し、ビルドへ影響する値は指紋へ反映する。
設定や環境変数全体をログへdumpしない。診断に値を出せない項目はdigestだけを記録する。

## ビルド指紋

指紋は版付きの形式とし、SHA-256の内容hashで入力を識別する案とする。
これは再ビルドと再現性のための識別であり、DLLの署名・発行者への信頼を証明するものではない。
外部Rustクレートを使わない方針の下で、hash実装と既知ベクトルによる検証も実装対象に含める。

| 入力 | 記録する内容 |
|---|---|
| プログラム | 入口と読み込んだ全ソースの名前・内容、関連するmanifest、依存の対応関係 |
| コンパイラ | 実際の実行ファイルの内容hash、compilerの版、資源ABI、選択した実行器 |
| runtime | 埋め込まれたCソースと追加の接続処理、生成用の設定 |
| 対象とオプション | target、profile、最適化、LTO、sanitizer、ABIに影響する設定 |
| C toolchain | 実際のcompiler/linkerの同一性と版、選択したSDK、実際に使うヘッダーと依存入力 |
| ネイティブ依存 | 能力集合、ライブラリ・ヘッダー・配布DLLと依存DLLの内容と配置 |
| 出力 | 実行ファイルの内容hash、配布物の一覧と内容hash |

時刻だけで同じ内容と判定しない。時刻を保ったソース変更、同じ版番号のcompilerの差し替え、
DLLの同名差し替え、能力の追加・削除も検出する。
パスはOSの表現を保って識別し、表示用の置換文字や区切り変換による衝突を避ける。

指紋計算で読んだソースと、コンパイラが使うソースを同じsnapshotにする。
C compilerが読む依存も収集し、ビルド中にSDKやnative入力が変わった場合は、完成したと見なさず再試行または失敗にする。
初期段階は正しい再ビルドを優先し、内容hashの省略はimmutableな依存などを検証してから導入する。

古い出力に新形式の指紋がない場合は一度作り直す。指紋が壊れていても成功済みとは扱わない。
失敗したビルドの指紋を成功した出力へ付けない。

## 同時ビルドと出力の公開

出力単位のOSの錠を取得し、同じ出力へのbuild/runを整合させる。
古いPIDを書いたファイルがあるだけで永久に待つ方式にはしない。初期のRust 1.65制約も考慮して実装する。
対象・profileの異なる生成物は別の場所へ置く。

1. 入力を確定し、作業用の一意なディレクトリでビルドする。
2. 生成物・配布依存の整合を確認し、内容hashを作る。
3. native依存を内容hashごとの完成済みディレクトリへ置く。
4. 実行ファイルを公開し、対応する指紋を最後に公開する。
5. 途中で停止しても、出力hashと指紋が一致しなければ次回は再ビルドする。

実行ファイルと指紋の2ファイルを、無条件に同時に置換できるとは仮定しない。
Windowsで実行中のファイルを置換できない場合は診断を返し、旧生成物を壊さない。
依存DLLは実行中のアプリが使う版を上書きしない。hashごとの配置を使い、生成物が必要な版を指す。
cleanでも、利用中と判明したファイルを無理に破棄しない。自動GCのために稼働中アプリの参照を把握できたとは仮定しない。

## Windowsのリンクと配布

Windows SDKのsystem libraryは能力から固定の対応で選ぶ。
描画系のuser32/d3d11/dxgi/d2d1/dwriteなどを、すべてのプログラムへ常に付けることはしない。
libpqなど追加DLLは配置・対象アーキテクチャ・必要な関数・版・推移的な依存DLLを確認する。
MSVCとMinGWのオブジェクト・import library・CRTを、拡張子だけで混ぜてよいとは扱わない。

libpqの初期案は明示的な動的ロード。実行ファイルの場所から決まる、検証した絶対パスと制限した探索を使う。
作業ディレクトリやPATHから同名DLLを偶然拾わない。
SDKの開発用ファイルをそのまま配布物に混ぜず、必要なruntimeとライセンス文書を一覧にする。
配布物は別の場所へ移して起動する試験を行い、開発機の絶対パスに依存していないことを確かめる。

## run・test・jwc

`alice run`は既定がインタプリタであるという現仕様を保つ。
必要な能力がその配布compilerにない場合は、説明して拒否する。黙って別の実行器へ切り替えない。
明示したrun --nativeやbuildでは、選択した能力を含むruntimeを作る。

testは、要求するSDK・DLL・サーバーなどの条件を明示する。
条件不足・skip・成功を区別し、DBやGUIを通常のデバッグ照合で複数回操作しない。
明示比較では実行器ごとに独立した環境を用意し、実際に検証した能力とtargetを記録する。

jwcは現在aliceのパッケージに未対応である。名前空間・直接依存・能力収集・資源ABI・リンク・診断を
Rust版とそろえてから、jwcによるパッケージビルドが対応済みとする。
共有の設定解決結果を渡す方式を第一案とし、依存解決を2つの実装で別々に進化させない。

## 完了条件

| 試験 | 確認すること |
|---|---|
| 既存互換 | native宣言のないnew/build/run/testとパス依存の挙動が維持される |
| 能力 | 未使用の依存、読み込んだモジュール、推移依存、衝突、未知の能力、未対応target |
| 古い道具 | 旧manifestと新manifest、新ライブラリのABI要求が古いcompilerで誤って成功しない |
| 指紋 | 時刻を保った変更、compiler/runtime/flags/DLL/ヘッダーの変更、削除、元に戻す操作 |
| 整合 | ビルド中の変更、途中停止、壊れた指紋、出力の差し替え、失敗時に旧生成物を維持 |
| 同時操作 | 同一出力へのbuild/run、異なるprofile/target、錠を持つプロセスの終了 |
| 配布 | DLLの不足・同名差し替え・依存不足・architecture違い、移動先での起動、探索規則 |
| 実行器 | Rust/IR/ネイティブ/jwc、能力不足の診断、外部副作用が一度だけ起きる通常実行 |
| 既存安全性 | 不正なmanifest・パス・長さでpanicせず、必要な固定攻撃とsanitizer試験を維持 |

この文書は設計であり、設定例やビルド指紋が現行aliceで利用可能という報告ではない。
