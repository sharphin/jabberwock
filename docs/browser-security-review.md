# ブラウザの危険性調査（2026-11-01）

対象: `browser/`（外枠 chrome.html、本体 browser.jw、WebView2 エンジン jwe_webview2.cpp、金庫 vault_main.jw・vault_link.jw、std.keystore）。
やり方: **コードを読んだだけ**。実際に攻撃を試す検証は**未実行**（Windows の実機でも試していない）。
「要確認」は、コードからは決めきれず、実機で確かめる必要があるもの。

## まとめ

| 重さ | 件 | 一言 |

| 高 | 1. ページが開く新しいタブの URL を調べていない | 罠のページが `data:` や `file:` のタブを開ける恐れ（要確認） |
| 高 | 2. アドレス欄に鍵マーク・http の警告がない | 暗号化されていないサイトでも見分けられない |
| 中 | 3. `WebView2Loader.dll` を名前だけで読む | 同じフォルダに偽の DLL を置かれると乗っ取られる |

| 中 | 5. ページで開発者ツール（F12）が使える | 他人に操作されて金庫の自動入力を盗み見られる余地 |
| 中 | 6. ダウンロードを WebView2 任せにしている | 実行ファイルを落とす前の確認・警告を自分で出していない |

## よくできている所（読んで確かめた）

- ページからブラウザ本体へのメッセージは**止めてある**（`IsWebMessageEnabled` は外枠だけ、`AreHostObjectsAllowed` は FALSE）。ページから「履歴を消す」などの命令は送れない。
- 外枠（chrome）は `data:` 以外へ移れない。ページの題名は `textContent` で出すので、題名に HTML を仕込まれても動かない（`innerHTML` は使っていない）。
- カメラ・マイク・位置情報・通知などの許可は**全部断る**。
- WebView2 自身のパスワード保存・自動入力は切っている（ただし SDK の版によっては切る処理が入らない。下の 11）。
- 金庫は別プロセスで、パイプでだけ話す。ほかのプロセスからはつなげない。
- 自動入力は、ブラウザ側で URL の出どころを比べ、さらにページの中で `location.origin` をもう一度比べる（二重）。書いたスクリプトの文字列は `SecureZeroMemory` で消す。
- クリップボードは 30 秒で消し、Windows のクリップボード履歴・クラウド同期に載らない印を付けている。
- PIN は 1 回間違えると覚えていた鍵を忘れる（総当たりできない）。
- 金庫の暗号は PBKDF2-SHA256（60 万回）＋ ChaCha20-Poly1305。起動時に試験ベクタで自己検査する。

## 1つずつ

### 1. ページが開く新しいタブの URL を調べていない（高・要確認）→ 直した（http・https だけ開く）
`NewWindowRequested` で受けた URL を、そのまま `new_tab(u)` → `navigate` している（browser.jw 396 行）。
ページ自身の移動なら Chromium が `data:` や `file:` へのトップの移動を止めるが、**ブラウザ本体が開き直すと、その制限を通らない**恐れがある。
`data:` のタブは偽のログイン画面（フィッシング）に使われやすい。`file:` は手元のファイルを見せる入口になる。
**直し方**: ページから来た新しいタブは `http:` `https:` だけ通し、ほかは捨てる（または外枠で確認を出す）。

### 2. 鍵マーク・http の警告がない（高）
アドレス欄は URL を出すだけで、暗号化の有無を示さない。http のログイン画面に打ち込んでも気づけない。
金庫の自動入力は出どころ（`http://` と `https://` は別）で比べるので、http 版へは入らない点は良い。
**直し方**: http なら「保護されていない通信」と出す。証明書エラーは WebView2 の既定（エラー画面で止める）のままで良いが、「進む」を出さないことを確かめる。

### 3. `WebView2Loader.dll` を名前だけで読む（中）→ 直した（WebView2 本体を絶対パスで読む。システムの DLL は System32 からだけ）
`LoadLibraryW(L"WebView2Loader.dll")`。Windows はまず exe と同じフォルダを探すので、
**ダウンロードフォルダで exe を開いた時、そこに偽の DLL があると読まれる**（DLL の差し替え）。
**直し方**: exe のフォルダの絶対パスで読む、または `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_APPLICATION_DIR | ...SYSTEM32)`。ほかの DLL 読み込み（crypt32.dll など）も `SetDefaultDllDirectories` でまとめて絞ると安心。

### 4. 金庫を名前だけで起こす（中）→ 直した（ブラウザと同じフォルダから絶対パスで起こす）
`process.start("jwvault-app", ...)` は `CreateProcessW(NULL, ...)` になり、exe のフォルダ → 作業フォルダ → システム → PATH の順に探す。
同じフォルダに本物があれば本物が起きるが、無い・消された時は**偽の金庫が起き、マスターパスワードを盗まれる**。
**直し方**: ブラウザの exe と同じフォルダの絶対パスで起こし、無ければ起こさずにエラーにする。

### 5. 開発者ツールが使える（中）
`AreDevToolsEnabled` を設定していないので既定（使える）。自分で使う分には便利だが、
誰かに「F12 を押してこれを貼って」と言われると、ページの中身や自動入力されたパスワードを読まれる。
**直し方**: 既定で切り、設定で入れられるようにする。

### 6. ダウンロード（中）
`DownloadStarting` を扱っていないので WebView2 の既定の動き（自動で保存）。exe などの危ない種類の確認や保存先の選択を自分では出していない。
**直し方**: `DownloadStarting` を受け、保存前に外枠で確認を出す。

### 7. 履歴などが平文（低）
`%LOCALAPPDATA%\jabberwock-browser` の history.tsv・bookmarks・settings・Cookie は暗号化していない（Chrome なども Cookie 以外は同じ程度）。
同じユーザーで動く悪いソフトからは守れない。金庫の中身（パスワード）は暗号化してあるので対象外。

### 8. 「この PC で覚える」（低・前提）
`vault.key` は DPAPI で守るので、ほかの PC やほかのユーザーには解けない。**同じユーザーで動くソフトには解ける**。設定の説明に書いたとおりの前提。

### 9. 隠した金庫の鍵（低・仕様）
「ブラウザを開いている間」は窓を閉じても鍵をメモリに持つ。5 分で閉じる「off」を選べば短くなる。

### 10. ポップアップ（低・要確認）
新しい窓の要求は全部タブにしている。ユーザーが押していないのに開く窓を止める処理はない。Chromium 側で止まるかは実機で確かめる。

### 11. 自動保存を切る処理の条件（低）
`ICoreWebView2Settings4` が SDK に無いとき、パスワード自動保存を切る処理がまるごと抜ける（`#ifdef`）。今使っている SDK にはあるが、古い SDK で作ると黙って抜ける。
**直し方**: 無ければビルドを失敗させる（`#error`）。

## 直す順のおすすめ

1 → 4 → 3 → 2 → 5 → 6。1・3・4 は数行ずつで直せる。直したら Windows の実機で、罠のページ（`window.open("data:...")`、偽の DLL・偽の金庫を置いたフォルダ）で確かめる。
