# 標準ライブラリの配置・読み込み仕様

状態: 実装前の設計。以下のimport記法、配布構成、依存指定は現行機能ではない。
[全体方針](standard-libraries.md)、[現在のパッケージ仕様](packages.md)、
[aliceのネイティブ依存](alice-native.md) に接続する読み込みの契約を定める。
設定ファイル全体の正式仕様は [aliceの設定仕様](alice-configuration.md) に定める。
資源ABIの確定、GUI内部の詳細設計は、この文書の完了とは別に扱う。

## 現在の動作と維持するもの

現在の`use geom;`は、単体ファイルなら入口と同じディレクトリのgeom.jw、
aliceなら利用元パッケージ内のモジュール、続いて直接依存の入口を探す。
依存先の内部モジュールはその依存先からだけ使え、推移的な依存先は自動では公開しない。
自分のモジュールと依存先の名前が同じ場合はエラーになる。

初期導入でユーザーのディレクトリ構成を階層化せず、これらの解決規則を維持する。
標準モジュールを同名の通常モジュールへ暗黙に置き換えたり、従来の裸の名前を標準側へ奪ったりしない。
Option/Resultなどの既存preludeとread_file/write_fileなどの組み込みも、この導入だけでは変更しない。

## importと利用名

追加する形式は次のとおり。例のAPIは設計中であり、現在実行できるコードではない。

```text
use geom;                  // 従来どおり。パッケージ内または直接依存
use std.fs;                // 標準fs。利用名はfs
use std.net;               // 標準net。利用名はnet
use std.time as clock;     // 標準time。利用名をclockにする
use geom as shapes;        // 通常のモジュールにも明示的な別名を付けられる
```

- 文法は`use 識別子 [as 識別子];`と`use std.識別子 [as 識別子];`に限定する。
- 標準の利用名は末尾の識別子。`use std.fs;`の後は`fs.read_bytes(...)`や`fs.Path`を使う。
- stdというまとめ用の値やモジュールを自動では束縛しない。`std.fs.read_bytes(...)`を利用記法にはしない。
- `use std;`は従来どおり通常モジュールstdを探す。stdという既存のファイル名・パッケージ名を全面的には予約しない。
- `use std.fs;`のstdだけが標準の指定を表す。ローカルのstd.jwやstd/fs.jwでは上書きできない。
- ワイルドカード、個別の関数の取り込み、importの再公開、一般の`use a.b.c;`は初期範囲に含めない。
- 大文字小文字を区別するASCII識別子を使う。パス文字列、`..`、区切り文字をimportへ直接書かせない。
- useはファイルのトップレベルに限る。コメントや文字列中のuseを依存として数えない。

同じファイルで同じモジュールを2度importすることは、別名を変えても重複エラーとする。
同じ利用名を別のモジュールへ割り当てた場合もエラーにする。
トップレベルの型・関数・変数などと利用名が衝突した場合は、その宣言とimportの位置を示す。
利用名を変える必要がある場合はasを使う。既存の変数名・シャドーイングの規則も適用する。

```text
use fs;                     // 自分のfs.jw
use std.fs as files;         // 標準fsとは共存できる
```

別名はそのファイルの名前解決にだけ使い、別ファイルや依存先へ流出させない。
別名が違っても、同じ標準モジュールのPathやFileは同じ型である。
型名・関数名の内部表現は解決済みのモジュールIDに結び付け、別名の文字列で型を複製しない。

## 標準モジュールと選択式パッケージ

標準モジュールはツールチェーンに同梱し、manifestへの直接依存の記載なしで明示importできる。
これは通常パッケージの推移的依存を公開する例外にはしない。利用者・依存先のどちらも自分のファイルにuseを書く。

| 標準モジュール | 初期の責任 | ネイティブ能力 |
|---|---|---|
| std.fs | Path、ファイル、ディレクトリ | fs |
| std.net | アドレス、DNS、TCP | net |
| std.tls | 検証付きTLSクライアント、TcpStreamからの変換 | net、tls_client |
| std.time | 単調時計、Duration、Deadline | 共通runtimeの時計処理 |

TLSを別モジュールにすることで、TCPだけのアプリにTLS基盤を要求しない。
期限やPathなど、複数モジュールが使う型は定義元を一つにする。
std.tlsのTcpStreamや各I/OのDeadlineは、std.net、std.timeが定義する型と同一である。
利用者が定義元を直接importしていなくても戻り値の型推論は可能だが、定義元の名前が自動で使えるようにはしない。

GUI・描画・PostgreSQLは標準の自動探索へ混ぜず、直接依存として選ぶ同梱パッケージとする。
初期のパッケージ名はwindow、draw2d、image、gui、postgresとし、各公開名と内部モジュールの分割は個別APIで確定する。
guiからwindow/draw2d、draw2dからwindowなど、必要な依存は各パッケージ自身が宣言する。
符号化画像の復号はimageを明示的に選び、raw pixelの描画だけでは要求しない。

同梱パッケージを選ぶ依存指定は次の案を採る。alice設定仕様のmanifest v2で同時に導入する。

```toml
[dependencies]
postgres = { bundled = "postgres" }
gui = { bundled = "gui" }
```

- bundledは選択中のツールチェーンのカタログから取得する。ネット取得や利用者ディレクトリの探索はしない。
- 初期は依存名とカタログのパッケージ名を一致させる。別名や版の選択は導入しない。
- pathとbundledは排他的な依存元。同じ依存に両方書いた場合、未知の依存元、未知の同梱名はエラーにする。
- `use postgres;`はこの直接依存を通じてsrc/lib.jwを読む。依存指定なしでは同梱されていても読めない。
- 利用者がpathで選んだ同名パッケージを、同梱版へ黙って差し替えない。
- グラフ全体で同じパッケージ名が別の場所を指した場合は従来どおりエラー。同梱版とpath版の混在も例外にしない。
- guiの依存として読んだdraw2dをアプリが直接useするには、アプリにもdraw2dの直接依存を書く。

旧aliceは未知の設定を読み飛ばすため、bundledキーだけで旧版が安全に拒否するとは約束しない。
新しいimport構文、コンパイラのABI要求、manifestの形式版と連携プロトコルを併せて検査する。
直接依存が欠けた状態を、同名のローカルファイルや別の配布先で補完しない。

## 配布構成とツールチェーンの選択

初期の配布構成は次を基準とする。配置自体も新仕様であり、現在のリポジトリに存在するという意味ではない。

```text
toolchain/
  bin/                         jabberwock、alice、jwc
  lib/jabberwock/
    catalog.json               版、標準ABI、対応target、公開module、同梱packageの対応
    std/                       fs.jw、net.jw、tls.jw、time.jw、内部の補助ソース
    packages/
      postgres/alice.toml
      postgres/src/lib.jw
      window/、draw2d/、image/、gui/
```

カタログは版付きのデータとして読み、必須項目・重複キー・重複ID・相対パス・長さ・要素数を検査する。
記載していない公開moduleや内部の補助ファイルを、ディレクトリの走査で自動公開しない。
初期配布は一つのコンパイラ版・標準ライブラリ版・資源ABIを対応付け、互換性の範囲を推測しない。
ネイティブDLLやSDKをこの構成に置いただけでは選択・ロードせず、alice-nativeの解決規則を適用する。

ツールチェーンのルートは次の順で一つだけ選ぶ。

1. 利用者がコマンドで明示した`--sysroot PATH`。
2. 単体のコマンドでは、実行中のコンパイラの実体の配置から求めた配布ルート。
   aliceは選択したコンパイラの配布ルートを問い合わせ、alice自身の隣にある別版を使わない。
3. 埋め込み利用では、呼び出し元が構築した明示的なツールチェーン情報。既定の配布ルートがなければ標準機能は利用不可。

3は1・2の失敗時に外部を探索するfallbackではなく、埋め込み用APIの入口を表す。
明示ルートの不備、カタログの破損、版・ABIの不一致では停止し、次の候補へ切り替えない。
PATHはコマンドを選ぶ既存の操作にだけ使い、標準ソースの探索先にはしない。
作業ディレクトリ、プロジェクト内の標準風ディレクトリ、環境変数のパス一覧、ネットワークを追加の候補にしない。

標準を使わない既存のプログラムは、既定の標準配布がなくても従来どおり動くようにする。
ただし--sysrootを明示した場合は利用がなくても指定を検証し、壊れた明示設定を成功として無視しない。
配布ルートを移動しても動くよう、カタログはルート内の相対パスを持ち、ビルドしたマシンの絶対パスを固定しない。
パスはOSの表現を保持し、空白・日本語・Windowsの長いパスを試験する。

カタログ内の絶対パス・親への移動を拒否し、リンクを解決した最終ファイルも配布ルート内か確認する。
各ソースは確認したファイルから一度読んだsnapshotを使い、名前解決と内容hashと実際のコンパイルを一致させる。
更新中の配布物を混ぜないよう、検証後に内容が変わった場合は再試行または失敗にする。
これはツールチェーンを信頼して利用するための整合検査であり、同一利用者による配布物の改変を防ぐOSの隔離ではない。

## 名前解決と公開範囲

| 指定 | 解決先 | 見つからない場合 |
|---|---|---|
| 単体ファイルのuse geom | 入口と同じディレクトリのgeom.jw | エラー。標準・他の作業ディレクトリへは進まない |
| aliceのuse geom | 利用元のパッケージ内、または直接依存geomの入口 | エラー。推移依存は見せない |
| use std.fs | 選択したカタログの公開ID std.fs | エラー。同名の通常モジュールへは進まない |
| 同梱postgres内のuse helper | postgres自身の内部モジュール | なければpostgresが直接宣言した依存だけを調べる |

ローカルモジュールと直接依存の同名衝突は、別名の有無にかかわらず現在のパッケージ検査で拒否する。
asは解決済みモジュールの利用名を変える機能であり、曖昧な依存元を選ぶ機能ではない。

公開ID、パッケージの同一性、内部モジュールID、実際のファイルパス、ファイル内の利用名を別々に持つ。
標準IDは利用者のパッケージ名や内部の区切り文字と衝突しない専用の分類にする。
初期の通常パッケージは従来どおり名前ごとに一つの場所へ解決し、複数版の同時利用は導入しない。
キャッシュ済みのモジュールでも、利用元からの直接依存・公開範囲を毎回確認してから返す。

標準の内部補助ソースはカタログ上でprivateとし、標準内からの参照だけを許す。
関数・型のpubによる公開規則も従来どおり適用する。privateな内部APIを別名や推移依存で公開しない。
importの再公開は提供しない。公開関数の型に依存先の公開型が現れても、依存先の名前空間そのものは公開しない。

一般のユーザーソースを標準風の名前にしただけでは、ネイティブ資源を作る内部操作を宣言・呼び出しできない。
内部操作の登録はコンパイラが知る能力・ABI・定義元IDと、検証した配布の内容に結び付ける。
path依存、コメント、manifestの任意キー、通常の関数名を根拠に特権を与えない。
カタログのhashは内容の識別であり、配布者の署名や信頼の証明とは区別する。

## 読み込みの手順と失敗

1. 入口とmanifestを確定し、利用元ごとの直接依存表を作る。
2. トップレベルのimportを文法として読み、種類・指定先・別名・位置を保持する。
3. 利用元を含む解決要求からmodule IDを決め、公開範囲を検査する。
4. 読み込み中のIDへの参照を循環として拒否し、依存の経路を示す。
5. ソースをsnapshotへ読み込み、内容hashと元のファイル位置を記録する。同じIDは一度だけ解析する。
6. 公開情報とファイルごとの別名表を作り、IDに基づく名前へ解決して型検査以降へ渡す。
7. 実際に読み込んだグラフから能力を集め、実行器とtargetで利用可能かを実行前に検査する。

useの先読みと本解析で別々の簡易文法を使わない。現在のUse直後の識別子だけを見る処理は、
ドット・as・区切りまで同じ規則で検査する処理へ置き換える。
読めないファイルを存在しないファイルと同じNoneへ潰さず、不在・権限・不正なUTF-8・I/O失敗を区別する。

モジュール数・依存辺数・深さ・ソースの個別サイズと合計サイズに上限を持ち、無制限な再帰で探索しない。
初期値と設定方法はalice設定仕様のlimitsに定め、上限超過は読み込み段階の診断にする。
循環・共有依存・重複パスでもファイルを無制限に読み直さない。
importされたモジュールの初期化としてユーザーコードや任意のビルドスクリプトを実行しない。

## 能力・ビルド・各実行器

能力の対象は実際に読み込んだ標準モジュールとパッケージ。
manifestに未使用のguiがあるだけでGUIをリンク・ロードしない。
読み込んだパッケージの能力は、未使用関数を除去できると仮定せず含める。
std.netを使うだけではtls_clientを加えず、std.tlsを読み込んだ場合に加える。
対応しないtargetや能力を要求したときは明確に失敗し、別実行器や別backendへ黙って切り替えない。

ビルド指紋には、カタログの形式・内容、選択した標準版・ABI、解決したIDと依存辺、
読み込んだ全ソースの内容、同梱packageのmanifestと依存元を含める。
入力のsnapshotと指紋の契約、リンク・DLL・公開途中の失敗はalice-nativeの設計を使う。
単なるルート移動による再ビルドは許容するが、同じ名前・版のまま内容を差し替えた際のキャッシュ誤用は許さない。

Rust版・IR・ネイティブ・jwcは同じ解決済みグラフ、ソースsnapshot、能力・ABI情報を使う。
workerでのモジュール再読み込みにも同じ情報を渡し、workerが別のディレクトリや新しい配布版を選ばないようにする。
グラフを外部ファイルとして渡す場合も、形式版・ID・依存の可視性・内容hash・ABIを受け側で検証する。
そのファイル自体を内部操作の特権を得る根拠にはしない。

jwcは現状aliceのパッケージ未対応である。字句・構文・型名の解決・診断・能力選択まで同じ規則を実装し、
単体実行とalice経由の両方を検証してから対応済みとする。
読み込みだけに成功したことを、資源操作や外部副作用の制御まで実装済みとは扱わない。
通常のアプリ実行をAST/IR/ネイティブ比較のために複数回実行しない規則も、共通資源管理に従う。
std.timeの時計の観測も非決定的な外部入力として扱い、通常の実行では自動再実行しない。
能力から必要なリンク処理を選ぶ判定と、自動照合を抑止する副作用・外部入力の判定を混同しない。

## 診断と完了条件

診断はimportの位置、利用元パッケージ、要求した公開ID、エラーの原因を示す。
衝突は両方の宣言元、循環は経路、ABI不一致は要求値と実際の値を示す。
privateと不存在、能力不足とSDK/DLL不足も区別する。
ソース一覧では論理IDと診断用のパスを対応付け、パスの表示文字列をファイルの識別に再利用しない。
設定全体や接続情報を診断へdumpしない。

| 検証 | 完了条件 |
|---|---|
| 既存互換 | 標準配布なしの従来プログラム、prelude、裸のuse、path依存、同名衝突の試験が通る |
| 文法 | std指定・as・不正なドット・重複・コメント/文字列・宣言との衝突を両コンパイラで一致させる |
| 分離 | ローカルfs/stdと標準fsの共存、別ファイルの別名、同じ標準型の同一性を確認 |
| 可視性 | private、直接/推移依存、キャッシュ済み依存の迂回、同梱依存の未宣言を拒否 |
| 配布 | 空白/日本語のパス、ルート移動、明示ルートの不備、欠損/破損カタログ、リンクによる逸脱を検証 |
| 同一性 | 同名別場所・path/bundled競合・版/ABI不一致・標準風ユーザー定義の内部操作を拒否 |
| 再ビルド | 時刻を保った標準変更、カタログ/manifest/能力変更、snapshot作成中の更新を検出 |
| 選択 | std.netだけではTLS不要、未使用GUIは不要、実際のTLS/GUI/DB要求は能力不足を見逃さない |
| 堅牢性 | 循環、深い/大きいグラフ、不正文字列、読取り失敗、上限超過でpanicせず診断する |
| 実行器 | Rust/IR/ネイティブ/jwc、単体/alice/workerで解決ID・型・結果・診断が一致する |

新しい読み込み経路は固定攻撃・生成入力と既存の安全性1〜7の検証対象にも加える。
ここに記した試験は実装後の完了条件であり、この設計書の作成によって合格したものではない。
