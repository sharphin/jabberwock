# 軽量ブラウザの試作: 実現可能性と構成案

状態: 方針を決めるための案（2026-10-30）。まだ何も実装していない。

## 結論

- **作れる。ただし今の jabberwock には C の部品を呼ぶ手段がない**ので、そこを最初に足す必要がある。
  標準ライブラリの設計（`docs/stdlib-v1-design` ブランチ）は「任意の FFI は初期版の外」としているので、
  なんでも呼べる FFI ではなく、**ブラウザ用の小さな部品（`webview` 能力）を 1 つだけ足す**形を勧める。
- エンジンは **第 1 段階で WebView2**（Windows に最初から入っている Edge のエンジン）を勧める。
  実行ファイルは数百 KB で済み、今のサイトがそのまま動く。
- アカウントの概念は「作らない」で消せる: ログイン・同期・プロファイル切り替えの画面も保存先も持たない。
  データの置き場所は 1 か所だけ（ブックマーク・履歴はただのファイル）。
- 後で jabberwock でエンジンを書き直すときは、**JavaScript なしの HTML/CSS 表示**から始めるのが現実的。
  そのとき要るもの（HTTP・TLS・文字の描画・画像）は、標準ライブラリの設計とほぼ重なる。

## エンジンの候補

| 候補 | 大きさ | 今のサイト | jabberwock から使う手間 | 向き不向き |
|---|---|---|---|---|
| **WebView2（勧める）** | exe は小さい（エンジンは OS 側） | ほぼ全部動く | COM なので C の薄い層を 1 枚かませる | Windows 専用。ログイン・同期は元から無く、パスワード保存・自動入力も切れる |
| webview/webview（C ライブラリ） | 小さい | 動く（中身は WebView2 / WebKitGTK） | C の API があり楽 | Windows と Linux 両方。ただし「止まって呼び返す」作りで、jabberwock の「取りに行く」作りに合わせる手直しが要る |
| CEF（Chromium） | 150〜250 MB | 全部動く | C の API が大きい | 「ごく軽量」に合わない |
| Servo | 中くらい | 一部 | C の API が無い（Rust の API だけ） | 外部クレートを使わない方針とぶつかる |
| litehtml | 非常に小さい | JS が動かない | 描画・通信・画像を全部こちらで用意 | 書き直しの練習台には良いが、第 1 段階では動くサイトが少なすぎる |

推測を含む点: WebView2 の細かい設定名（`IsPasswordAutosaveEnabled` など）は実装時に SDK の版で確かめる。

## 構成（WebView2 の場合）

```
jabberwock のプログラム（browser.jw）
  ├─ タブ・URL の補完・履歴・ブックマーク・設定 … ここを jabberwock で書く
  ├─ 画面の外枠（アドレスバー・タブ列）… 小さな HTML。WebView2 で表示し、押されたら jabberwock へ知らせる
  └─ std の webview 能力（新しく足す）
        └─ C の薄い層 jw_webview.c（WebView2 の COM を隠す）
              └─ WebView2（OS に入っているもの）
```

- **呼び返しはしない**。C の層がイベント（読み込み完了・タイトル変更・アドレスバーで Enter など）を溜め、
  jabberwock が `poll_events()` / `wait_events(期限)` で取りに行く。GUI 設計の Window と同じ形で、
  所有・世代の安全の考え方がそのまま使える。
- 外枠を HTML にすると、標準ライブラリの GUI（まだ未実装）を待たずに作り始められる。
- インタプリタでは動かさず、`jabberwock build` で作った実行ファイルだけで動く（インタプリタでは「build してください」のエラー）。

### アカウントを持たない、の具体的な中身

| 項目 | 扱い |
|---|---|
| ブラウザへのログイン・同期・プロファイル | 画面も保存先も作らない |
| パスワード保存・自動入力 | WebView2 の設定で切る |
| 保存場所 | `%LOCALAPPDATA%\jabberwock-browser\` の 1 か所だけ。ブックマーク・履歴は読めるテキストファイル |
| サイトの Cookie（サイトへのログイン） | 下の「決めたいこと」 |

## jabberwock 側に足りないもの（標準ライブラリのスレッドへ渡す一覧）

第 1 段階（WebView2 で動かす）に必要:

| 種類 | 足りないもの | 今あるもの・設計との関係 |
|---|---|---|
| 言語・ビルド | C の部品をつなぐ手段（`webview` 能力として登録・リンク） | 設計の alice-native「能力」の仕組みに乗せる。未実装 |
| イベント | `poll_events` / `wait_events(期限)` の形 | GUI 設計に同じ形がある。未実装 |
| 時刻 | 今の時刻（履歴の日時）・待つ | ない |
| ファイル | フォルダを作る・あるか調べる・一覧・消す・安全な上書き | `read_file` / `write_file` だけ。File 設計で予定 |
| 環境 | 環境変数（`LOCALAPPDATA`）・アプリ用フォルダの場所 | ない |
| データ形式 | JSON の読み書き（外枠の HTML とのやりとり・保存ファイル） | ない。設計にもない（推測: 追加が要る） |
| 文字列 | URL の分解・%エンコード、検索語か URL かの判定 | `split` / `find` / `replace` などはある。URL 専用はない |

書き直し（自前エンジン）の段階で必要:

| 種類 | 足りないもの | 設計との関係 |
|---|---|---|
| 通信 | HTTP/1.1 クライアント（chunked・リダイレクト・gzip） | TCP/TLS は設計済み、**HTTP は初期版の外** |
| 圧縮 | deflate/gzip の展開 | ない |
| 描画 | 2D 描画・文字の配置（DirectWrite） | 設計済み・未実装 |
| 画像 | PNG/JPEG の展開 | WIC で設計済み・未実装 |
| 解析 | HTML の字句・木構造、CSS の解析・カスケード、レイアウト | jabberwock で書く本体 |
| JavaScript | なし（入れない前提を勧める） | — |

## 進め方（案）

1. `webview` 能力の最小形: 窓を開く・URL を開く・イベントを取る・閉じる（Windows、`jabberwock build` だけ）。
2. browser.jw: アドレスバー・戻る/進む・再読み込み・タブ 1 枚。
3. 履歴・ブックマーク（ファイル保存）・複数タブ。
4. （余裕があれば）JS なしの自前表示エンジンを別ウィンドウで試し、WebView2 と並べて比べる。

注意: この作業環境は Linux なので、WebView2 の動作確認はまつさんの Windows で行う必要がある
（C の層のビルドと動作確認だけ、手元での実行をお願いすることになる）。
